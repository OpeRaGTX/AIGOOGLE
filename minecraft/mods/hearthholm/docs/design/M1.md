# 20. Волна M1: баги и мелочи

[← DESIGN](../../DESIGN.md) · [Для игрока](../waves/M1.md)

- **`util/Labels`**: `orHumanized(key)` = `Component.translatableWithFallback(key, humanize(key))`; работает на сервере и клиенте без обращения к `Language`. Используется в
  `Blueprint.label()` и `SiteOption.valueLabel` (динамические варианты). Единое место для «никогда не показывать сырой ключ»: другие списки подключаются одной строкой.
  Защита на этапе сборки: `tools/gen_lang.py` проверяет, что у каждого id из `blueprints/index.json` есть название (RU+EN из одного кортежа).
- **`Workshop.smelts()`**: у мастерской есть рецепты «готовки» (`cooking(type)`). `SettlementService` выбирает сообщение `workshop_ok` (с подсказкой печи) или `workshop_ok_plain`.
- **Владельцы и поселенцы**: единственный шлюз `SettlerEntity.isProtectedOwner(Entity)` (основатель или совладелец, `SettlementService.isOwnerOrCoOwner`, без обхода по творческому режиму).
  Его используют `canAttack` (все цели целеуказания Minecraft проверяют его), `setTarget` (цель-владелец отбрасывается) и `hurtServer` (после удара владельца `lastHurtByMob` сбрасывается).
  Урон проходит. `callGuards` и так не реагирует на игроков.
- **Уведомления**: `SettlementService.notify` рассылает всем из `onlineManagers(st, lookup)` (основатель + совладельцы онлайн, без дублей). Перегрузка с `lookup` нужна тесту: в нём один настоящий игрок.
- **Голод**: `SettlerEntity.hungerPerTick()` = `1/1800 * Balance.HUNGER_RATE_PERCENT/100 * черты`, во сне половина. Старое значение = 100.
- **Конец смены**: `BaseJob.keepPlan(settler, job)` возвращает для каждого слота число предметов, которые остаются (снаряжение целиком; бюджет еды `Job.shiftEndFood()`;
  припасы работы `Job.shiftEndKeep(settler, stack, keptSoFar)`). `hasUnloadable` и `unloadInto` читают один и тот же план, поэтому расходиться не могут.
  Профессия добавляет своё переопределением двух методов `Job` (шахтёр: факелы, лестницы, заполнитель до `SHIFT_END_KEEP_FILLER_MINER`, еда 8; строитель: лопата и кирки).
- **Инструмент под блок**: `entity/ai/jobs/ToolKit` (`Kind.PICKAXE/SHOVEL`, `kindFor(BlockState)` по тегам `MINEABLE_WITH_*`, `takeBest`). `BuilderJob.toolFor(state)` вызывается перед
  `BreakBlock` на шаге расчистки: `SettlerEntity.equipFromPockets(pred)`, иначе `ContainerTrip` к ближайшему сундуку/складу с таким инструментом (повтор не чаще
  `BUILDER_TOOL_RETRY_TICKS`, по одному таймеру на вид инструмента), иначе работа тем, что в руке. Старый `toolTrip()` из начала `next()` убран (профессиональный инструмент строителя
  теперь подбирается под блок). Новый вид инструмента = константа в `ToolKit.Kind` + строка в `kindFor`.
- **Тесты**: `WaveM1Test` (`HH_ONLY_M1=1`): имена и fallback, `smelts()`, FakePlayer (владелец, совладелец, чужой), аудитория уведомлений, коэффициент голода 2,5, `keepPlan` для шахтёра/дровосека/строителя,
  живая выгрузка шахтёра, живой строитель с киркой в сундуке и шахматным полом камень/земля, скриншоты колышка (RU/EN). Диспетчер волн в `HearthholmClientTest` теперь знает
  «самостоятельные» волны (`standalone`): они запускаются только по своему флагу или в полном прогоне; новая волна = флаг + имя в `standalone` + строка запуска.
